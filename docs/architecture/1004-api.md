# ARCH-1004 · API

**Doc ID:** `ARCH-1004` · **File:** `1004-api.md`

| Field | Value |
| ----- | ----- |
| Status | **Live** (Jun 2026) |
| Layer | API — HTTP Route Handlers, webhooks, cron, partner contracts |
| Defers to | **ARCH-1001** · **ARCH-1002** (backend) · **ARCH-1003** (frontend) · **ARCH-1005** (platform) |

**Authority:** This doc defines the **required** HTTP API shape. Anything that does not match §2–§6 is **non-compliant** — not deferred work, not a permissive legacy exception. Agents and PRs **follow target only** (**ARCH-1001** §7).

---

## 1. Core rule

> REST is for **contracts** outside the page runtime — partners, webhooks, cron, streams, mobile. **Commands** are mutation authority; route handlers and Server Actions are **transports** only (**ARCH-1002** §2).

```txt
Partner / webhook / cron / stream  →  Route Handler (thin)  →  command / service  →  backend
Browser ERP page                   →  import @afenda/feature-*/server  (no self-HTTP)
```

| Transport | Dispatches |
| --------- | ---------- |
| Server Action | Same `*Command` types |
| REST Command API | Same `*Command` types |
| Webhook / cron / Lynx tool (after approval) | Same `*Command` types |

| Surface | Owns | Must not own |
| ------- | ---- | ------------ |
| Route handler | Parse, auth, org, dispatch | HR/finance policy, SQL, workflows |
| Domain service | Invariants, permissions, audit | HTTP, JSON shape |
| Presenter | API field labels | Authorization, state transitions |

**Product split:** approve/post/void/close period → **command**, not `PATCH`. Simple create/safe field update → resource API. Internal pages → **server queries**, not `fetch('/api/...')` (**ARCH-1003**).

## 2. Scopes and planes

Two URL scopes — different stability, auth, and rate limits:

| Prefix | Callers | Stability | Rate limit |
| ------ | ------- | --------- | ---------- |
| `/api/public/v1/*` | Partners, vendors | Strict semver; breaking → v2 | IP + scoped API key; strict WAF |
| `/api/internal/v1/*` | Lynx, cron, admin automation | Same release train | `userId` / service identity |

Four HTTP **planes** (split by intent, not one CRUD style):

| Plane | Shape | Rule |
| ----- | ----- | ---- |
| **Resource** | `GET/POST/PATCH/DELETE …/employees/{id}` | Safe CRUD only |
| **Command** | `POST …/commands/approve-purchase-order` | Workflows, posting, approvals |
| **Query** | `GET …/queries/workforce-headcount` | Read projections for external callers |
| **Event** | `GET/POST …/internal/v1/events` | Truth stream — internal only |

```txt
/api/{public|internal}/v1/<resource>/…
/api/{scope}/v1/commands/<verb-kebab>/…
/api/{scope}/v1/queries/<query-name>
/api/internal/v1/events/…
/api/internal/v1/webhooks/<provider>/…
```

URL rules: plural nouns; verb-kebab command names; no `POST /api/v1/approvePurchaseOrder`; additive JSON in v1 OK; rename/remove → version bump. Nested `…/{id}/approve` and flat `/api/<module>/…` without scope are **non-compliant**.

**Registry** — every command/query/webhook declares metadata in the feature package; `packages/registry` aggregates for System Admin (**ARCH-1006**). No HATEOAS / JSON:API `_links`.

Event envelope (writers = domain services after commands — not route handlers):

```json
{
  "eventId": "evt_001",
  "eventType": "employee.created",
  "occurredAt": "2026-06-02T12:00:00.000Z",
  "organizationId": "org_abc",
  "actor": { "id": "usr_1", "type": "user" },
  "resource": { "type": "employee", "id": "emp_123" },
  "payload": {},
  "correlationId": "req_abc"
}
```

Event types: dot notation — `po.approved`, `invoice.posted`, `leave.approved`.

## 3. Handler pipeline

Every endpoint:

```txt
parse → authenticate → resolve organizationId (server truth)
→ Zod → permission / scoped token
→ dispatch command OR domain service / read model
→ audit / domain event (via backend)
→ presenter JSON → standard error mapper
```

Required thin handler (every route):

```ts
export async function POST(request: Request) {
  return withApiHandler(request, async (ctx) => {
    const input = await parseJsonBody(request, createEmployeeInputSchema);
    const employee = await dispatchCreateEmployeeCommand({
      actor: ctx.actor,
      organizationId: ctx.organizationId,
      input,
    });
    return apiCreated(presentEmployee(employee));
  });
}
```

Governed mutations: route → `*Command` → `@afenda/kernel` → domain → repository → event. Routes **never** call `@afenda/db`, domain services, or AI orchestration directly.

### Code placement

| Concern | Location |
| ------- | -------- |
| Route | `apps/erp/src/app/api/{public\|internal}/v1/.../route.ts` — parse/auth/dispatch only (typically ≤15 lines) |
| Handler kit | `@afenda/api` — `withApiHandler`, envelopes, `dispatchCommand`, error mapper |
| Zod | `feature/*/schemas/` |
| Presenters, registry metadata | `feature/*/api/*.contract.ts`, `*.presenter.ts` |
| Stream/query ingress | `feature/*/api/*.handler.server.ts` — calls **commands**, **read-models**, or **domain** only |
| Commands | `feature/*/commands/` |
| Domain, repository | `feature/*/domain/`, `data/` |

`apps/erp/src/lib/api/` is **forbidden** for module Zod, presenters, `@afenda/db`, or Lynx/HR logic. App lib may re-export `@afenda/api` helpers only. Feature slice shape: **ARCH-1002** §8.

## 4. Response contract

Server Actions use `ActionResult` (**ARCH-1003**) — **different** from REST. Do not merge.

**Success:** `{ data, meta: { requestId, apiVersion: "v1" } }`  
**List:** `{ data, pagination: { cursor, hasMore }, meta }`  
**Error:** `{ error: { code, message, details }, meta }`

| Code | HTTP | Use |
| ---- | ---- | --- |
| `BAD_REQUEST` | 400 | Malformed |
| `VALIDATION_FAILED` | 422 | Field errors in `details` |
| `UNAUTHENTICATED` | 401 | Missing/invalid credentials |
| `PERMISSION_DENIED` | 403 | Known actor, denied |
| `NOT_FOUND` | 404 | Missing in tenant scope |
| `CONFLICT` | 409 | Uniqueness, version, state |
| `RATE_LIMITED` | 429 | Throttled |
| `INVARIANT_FAILED` | 422 | Business rule (safe message) |
| `INTEGRATION_FAILED` | 502 | External system |
| `INTERNAL_ERROR` | 500 | Logged; generic client message |

Never return Postgres/Drizzle/Zod stack traces.

**Lists:** `limit`, `cursor`, `sort`, `search`, status/date filters — prefer **cursor** for large tables; offset only for bounded datasets.

**Idempotency** — `Idempotency-Key` header on sensitive POST (payments, approvals, bulk import, journal create, inventory adjust, webhook dedupe). Tenant-scoped records in DB.

## 5. Ingress patterns

### Webhooks

```txt
POST /api/internal/v1/webhooks/<provider>
verify signature → store raw payload → dedupe → Zod → ingestion command → 2xx fast
```

Flat `app/api/webhooks/*` without `internal/v1` is **non-compliant**. Defer heavy work via `waitUntil` (**ARCH-1005** §9).

### Cron

```txt
POST /api/internal/v1/cron/<job>
Authorization: Bearer ${CRON_SECRET}   (apps/erp/src/lib/cron.ts)
```

Node.js runtime (DB transactions). `export const maxDuration = 300` or `vercel.json` glob — **ARCH-1005** §2.2. Flat `app/api/cron/*` is **non-compliant**.

### Lynx / AI streams

HTTP for **browser streaming only** — all orchestration in `@afenda/feature-lynx` (and `@afenda/ai` substrate), not in `route.ts`:

```txt
thin route → feature api handler
  → auth + capability (server org)
  → Zod (feature/schemas)
  → streamText / agent UI (AI Gateway)
  → tools with needsApproval → dispatchCommand
  → toUIMessageStreamResponse()
  → §4 envelope where JSON (not ad-hoc { error: string })
```

`maxDuration` 60s+; gateway auth: **ARCH-1005** §10.1.

**Required Lynx routes** (internal scope + plane):

| Route | Plane | Feature entry |
| ----- | ----- | ------------- |
| `POST /api/internal/v1/lynx/queries/truth-search` | query (stream) | `handleLynxTruthSearchPost` in `feature-lynx` `api/` |
| `POST /api/internal/v1/lynx/queries/operator` | query (stream) | `handleLynxOperatorPost` in `feature-lynx` `api/` |
| `POST /api/internal/v1/lynx/commands/record-run-feedback` | command | `executeLynxRecordRunFeedbackCommand` |
| `GET /api/internal/v1/lynx/queries/run-ledger-export` | query | read-model export in `feature-lynx` `read-models/` |

**Non-compliant:** flat `/api/lynx/*`, business logic or `@afenda/db` in `apps/erp/.../route.ts`, Lynx schemas in `apps/erp/src/lib/api/`, per-route JSON outside §4.

General AI assistant routes: `POST /api/internal/v1/ai/...` (same thin-route rule). Flat `/api/ai/*` is **non-compliant**.

### Blob uploads

`POST /api/internal/v1/uploads` (or documented internal upload contract) — auth in `onBeforeGenerateToken` before token mint. **ARCH-1005** §10.2. Flat `api/uploads` without scope is **non-compliant**.

## 6. Security

Minimum on every route:

```txt
org scoping (server-resolved) · permission before service · Zod + presenter at boundary
requestId in meta · audit on mutations · no raw DB models
```

| Auth | Use |
| ---- | --- |
| Scoped Bearer / API key | Partners (`hr.employee.read`, `finance.journal.write`, …) |
| Session cookie | Same-origin browser only |
| Cron secret | `/api/internal/v1/cron/*` only |

`proxy.ts` refreshes Neon Auth for navigation — **not** handler auth (**ARCH-1003**).

**Rate limits:** WAF path rules on `/api/public/*` (IP); `@vercel/firewall` `checkRateLimit(ruleId, { request, rateLimitKey? })` in `withApiHandler`; return `RATE_LIMITED` with §4 envelope. Detail: firewall dashboard + **ARCH-1005** §2.

**BotID:** public/anonymous POST — **ARCH-1003** §8.

**CDN cache:** non-tenant public GET only — `Cache-Control: public, s-maxage=…`; tenant data `private, no-store`. Runtime cache: **ARCH-1003** §9.

## 7. Non-compliance (wrong patterns)

Do **not** treat these as acceptable until a future phase. They are **wrong** relative to this doc.

| Pattern | Why it is wrong |
| ------- | ---------------- |
| Flat `/api/lynx/*`, `/api/ai/*`, `/api/cron/*`, `/api/uploads` without `public/v1` or `internal/v1` | §2 scope violation |
| Fat `route.ts` (auth + Zod + DB + AI + logging + revalidate in one file) | §1, §3 — transport only |
| `@afenda/db` or domain rules in `apps/erp/src/lib/api/` | §3 code placement |
| Ad-hoc `{ error: "..." }` / `{ ok: true }` without §4 `meta` and `error.code` | §4 response contract |
| Route calls `recordLynxRunFeedback` / `getLynxRunDetail` directly | Must dispatch feature **command** / **read-model** |
| `feature/*/api/*.handler.server.ts` imports `@afenda/db` | Handlers orchestrate; **data/** and **commands/** own SQL |
| Workspace pages `fetch('/api/...')` for tenant lists | **ARCH-1003** — server query in-process |
| Server Action `fetch` to own API for mutations | Same **command** in-process |
| `PATCH` for approve/post/void/close | Command plane only |
| Nested `…/records/{id}/approve` without `/commands/` | §2 planes |

**Required tree shape:**

```txt
app/api/
  public/v1/     … resources · commands · queries (partner)
  internal/v1/   … lynx · ai · cron · webhooks · uploads · observability
  auth/[...path]/  … Neon Auth (framework exception)
```

Build order (**ARCH-1001** §7): P1 `@afenda/api` + scoped routes → P2 all mutations via command + kernel → P3 events/projections → P4 registry. Skipping a phase does not relax §2–§6.

## 8. Anti-patterns

| Don't | Why |
| ----- | --- |
| Document or bless flat `/api/*` as acceptable | §7 — wrong, not deferred |
| Shim routes that duplicate feature logic “until migration” | No temporary architecture |
| Business logic in `route.ts` | Feature `commands/` / `domain/` / `api/` handlers |
| Workspace `fetch('/api/...')` for page data | In-process query (**1003**) |
| Server Action `fetch` to own API | `dispatchCommand` in-process |
| `PATCH` for approve/post/void | Command plane |
| Separate `apps/api` deploy | One app (**1001**) |
| Route handler invents events | Domain service after command |
| Skip org on “internal” routes | Tenant isolation always |

## 10. Summary

```txt
API = HTTP for external callers — same commands as Server Actions

Scopes:  public/v1 (strict)  vs  internal/v1 (release train)
Planes:  resource · command · query · event (+ registry metadata)
Flow:    thin route → Zod → command/service → §4 envelope
Ingress: webhooks · cron · Lynx streams · Blob (see §5)
Security: WAF + checkRateLimit · BotID on risky POST · no tenant CDN cache

Backend: ARCH-1002 · Frontend: ARCH-1003 · Platform: ARCH-1005 · Admin registry: ARCH-1006
```
