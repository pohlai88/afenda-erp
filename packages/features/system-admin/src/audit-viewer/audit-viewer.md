### 9.9 Audit Viewer

## Definition

Audit Viewer is the administrative evidence review surface.

It allows authorized administrators, auditors, compliance officers, and investigators to review the evidence generated by ERP activity.

Audit Viewer does not create audit events.

Audit Viewer does not enforce policy.

Audit Viewer does not determine permissions.

The Execution Kernel writes audit evidence.

System Admin reviews audit evidence.

## Owns

Audit Viewer owns:

* audit search
* audit filters
* audit export
* audit event detail view
* evidence timeline view
* evidence correlation review
* actor investigation
* target investigation
* audit coverage review
* audit retention visibility
* administrative evidence review

## Does Not Own

Audit Viewer does not own:

* audit event generation
* policy enforcement
* permission enforcement
* workflow execution
* approval execution
* business operations

Those belong to:

```txt
Execution Kernel
Policies
Permissions
Approvals
Orbit / Workflow
Feature Modules
```

## Core Principle

Audit Viewer answers:

```txt
What happened?
Who performed it?
What changed?
Why was it allowed?
What evidence exists?
```

Not:

```txt
What row changed?
```

    await requireExecutionContext()

  await requireExecutionPermission(

  return searchAuditEvents({
    organizationId: context.organizationId,
  })

## Export Action Pattern

```ts
export async function exportAuditEvidence(
  input: ExportAuditInput,
) {
  const context =
    await requireExecutionContext()

  await requireExecutionPermission(
    context,
    "system-admin.audit.export",
  )

  const parsed =
    exportAuditInputSchema.parse(input)

  const result =
    await generateAuditExport({
      organizationId: context.organizationId,
      filters: parsed,
    })

  await writeExecutionAuditEvent({
    organizationId: context.organizationId,
    actorId: context.userId,
    actorType: context.actorType,

    action:
      "system-admin.audit.export",

    targetType: "audit_export",
  })

  return result
}
```

## Safety Rules

Audit Viewer must enforce:

1. Organization scope is mandatory.
2. Audit events are immutable.
3. Audit Viewer cannot modify evidence.
4. Sensitive metadata must be redacted.
5. Export actions are audited.
6. Audit history cannot be deleted through Audit Viewer.
7. Policy references must be visible where available.
8. Approval references must be visible where available.
9. Evidence timelines must remain chronological.
10. Execution Kernel remains the source of truth.

## Definition of Done

Audit Viewer is done when:

* administrators can search audit events
* administrators can filter audit events
* administrators can inspect evidence details
* administrators can review evidence timelines
* administrators can investigate actors
* administrators can investigate targets
* administrators can investigate capabilities
* administrators can export evidence
* exports are audited
* sensitive data is redacted
* evidence is immutable
* audit coverage visibility exists

## Final Architecture Statement

Execution Kernel answers:

```txt
What evidence was generated?
```

Audit Viewer answers:

```txt
Can I understand, trace, investigate, and prove what happened?
```

Policies answer:

```txt
Why was it allowed or blocked?
```

Approvals answer:

```txt
Who authorized it?
```

Audit Viewer is Afenda's evidence investigation surface, not merely an audit log table.
